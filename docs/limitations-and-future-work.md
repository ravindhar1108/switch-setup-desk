# Limitations and Future Work

Honesty regarding system capabilities and boundaries is critical for open-source software and hackathon submissions. This document outlines current system limitations and identifies potential areas for future exploration.

---

## Current Limitations

### 1. Interface Dependency
- **Slack Required**: Setup Desk currently relies on Slack for conversational interaction and task triggering. Users without a configured Slack workspace or Switch Slack integration cannot interact with the workflow directly.
- **Switch Console Configuration**: Multi-agent rooms, handoffs, and backend bindings must be manually configured or imported through the Switch platform.

### 2. Operational & Platform Boundaries
- **No System-Level Package Installation**: Because Setup Desk operates strictly within an unprivileged project workspace, it cannot autonomously install missing host toolchains (e.g., installing a C++ compiler via `build-essential`, installing `cmake`, or provisioning system-level databases like PostgreSQL or Redis). Such requirements cause the workflow to halt and escalate to human operators.
- **Operating System Sensitivity**: The workflow executes on the host OS where the agent runner is hosted. Setup commands and path handling may behave differently on Windows, macOS, or Linux, and Scout can only check for compatibility signals when they are documented or raised in public discussions.

### 3. Recovery Constraints
- **Maximum 3 Repair Cycles**: Setup Desk strictly caps repair attempts to 3 iterations. Highly complex setup failures requiring extensive source-code refactoring or multi-library dependency resolution may exceed this limit.
- **Heuristic-Driven Remediation**: Repair is designed for common project-level issues (version pinning, missing environment files, build flags). It does not write complex architectural code patches or fix fundamental runtime bugs within the target project's core logic.

### 4. Language & Ecosystem Coverage
- Setup Desk's prompt specifications and agent behaviors have been tested primarily on common Python and Node.js project layouts. Projects using multi-language monorepos, specialized embedded toolchains, or complex compiled ecosystems (e.g., C/C++, Rust with system bindings) have not been extensively benchmarked.

---

## Future Work (Ideas for Exploration)

> [!NOTE]
> The items below represent conceptual roadmaps and future enhancements. They are **not implemented features** in the current hackathon release.

### 1. Broadened Language & Ecosystem Support
- Expand specialized agent instructions and detection rules for Rust (`cargo`), Go (`go mod`), Java (`gradle`/`maven`), and C/C++ (`cmake`/`conan`).
- Add support for monorepo build orchestration tools like Turborepo, Nx, and Bazel.

### 2. Containerized Sandboxing (Docker / Podman Integration)
- Instead of running on the local host workspace, dynamically spin up disposable Docker containers for each setup session.
- Allow agents to safely execute system-level installations (`apt-get install`, etc.) inside ephemeral containers without risking host system integrity.

### 3. Repository Compatibility Scoring
- Introduce a pre-flight "Setup Compatibility Score" generated by Scout before running Setup.
- Score repositories based on documentation completeness, age of dependencies, open setup-related issues, and platform support.

### 4. Persistent Setup Knowledge Base
- Cache verified `SETUP.md` guides and successful repair recipes across sessions in a shared community catalog.
- If a developer requests a repository that Setup Desk has previously resolved, Scout can instantly retrieve verified setup instructions and known fixes.

### 5. Automated CI / GitHub Action Integration
- Package Setup Desk as a reusable GitHub Action that validates whether new pull requests or dependency updates break clean local setup workflows.

### 6. Additional Agent Backends & Web UI
- Support additional model backends through Switch's extensibility layer (e.g., Anthropic Claude, Google Gemini CLI, local open-weights models).
- Develop an optional standalone web dashboard for teams that prefer browser-based workflow tracking over Slack.
